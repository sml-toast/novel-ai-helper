## 二、~~优先级 P0：M4 收尾补课~~（已完成，2026-09-05）

### F078 / T008 · 导出完整性 + 导入回灌 + 备份 ✅

原问题：`exportProject()` 只覆盖 6 块数据，且没有导入端点——「导出」是本工具唯一内建的
数据逃生通道，不完整等于数据安全承诺打折。交付内容：

- [x] `exportProject` 覆盖除 users / audit_logs 外的全部业务表（19 个集合）+ `formatVersion`/`schemaVersion`/`exportedAt` 元信息；密钥材料（cipher/salt）永不导出
- [x] 新增 `POST /import`：`new`（默认，重映射 ID 导入为新项目）/ `replace`（覆盖目标项目）；导入前 `VACUUM INTO` 整库自动备份（失败即中止）；全程单事务、失败整体回滚；非法载荷 400；global 共享数据「存在即跳过」防重复
- [x] 导出端点支持 `?projectId=`（否则导入出的新项目无法验证与再导出）
- [x] 契约用例 14–17（导出完整性 / 非法载荷 / new 往返比对 / replace 隔离性）+ curl 手动往返验证

> 与设计文档的偏差说明：原计划的 skip/overwrite/new 三种冲突策略收敛为 **new/replace 两种** ——
> 单用户单库场景下「skip 逐行去重」复杂度高而收益低，global 数据用「存在即跳过」覆盖了它的真实需求。

## 六、远期想法池（未立项、未评估工作量，仅记录方向）

以下条目**不属于承诺**，按价值/成本随评估随立项：

1. **端到端加密云备份**：解决「主密钥 + 库文件异地容灾」；须评审与 F073 密钥安全目标的兼容性（QA1 的延伸）。
2. **AI provider 插件化**：多供应商并存、按任务类型路由模型（如润色用本地模型、构思用云端强模型）；当前 provider 单链路可平滑演进。
3. **对话式改稿**：在流式输出（T015）之上叠加多轮会话记忆，从「一次性建议」走向「协同修订」。
4. **真实发布平台对接**：`simulatePublish` 之上替换真实 provider；需处理各平台鉴权与限流，建议逐平台单独立项。
5. **朗读/语音输入**：原任务计划 Phase 5 遗留想法；浏览器 Speech API 可零依赖起步。
6. **多语言界面**：UI 文案集中化后可低成本支持。

## 七、推进纪律（来自设计文档的经验教训）

1. **无测试保护不改契约**：T009 已建立防线，后续任何 API 语义变更先补契约用例再动手。
2. **新表新列一律走迁移**：追加 `MIGRATIONS` 条目，永不修改已发布迁移；迁移失败即启动失败是特性不是缺陷。
3. **版本表与审计表是高频路径禁区**：任何新增的高频自动行为（自动保存、自动提及扫描）不得写这两张表。
4. **零依赖红线先实测再下结论**：bigram、SSE、scrypt、busy_timeout 等结论全部来自一次性脚本实测
   （design 文档附录 A 的脚本清单可复跑）；新需求涉及「Node 内置能不能做」时先写探针脚本。
5. **密钥永不入库**：文档、代码、测试、提交信息一律不得出现真实密钥；出现即按 F073 流程处置。
