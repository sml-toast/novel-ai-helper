## 1. 产品目标（可衡量）

以下目标均锚定「零依赖 + 本地优先 + 可信可用」的产品哲学，并给出可复核的度量口径。截至 M6（2026-09-09 全部交付），带 ✅ 的为已达成。

### 1.1 数据安全与可信（安全目标）

- **G1 零明文密钥** ✅
  - 定义：API Key 不落库明文、UI 永不回显明文、不写入代码/测试/文档/提交信息。
  - 度量：`grep -rIn "sk-"`（或厂商密钥前缀）在源码、测试、文档、git 历史外的运行时内存扫描结果为 0；设置面板「保存 AI 配置」仅保存且加密（F075），回显为掩码。
- **G2 主密钥本地备份可引导** ✅
  - 定义：密钥加密材料（cipher/salt）由本机主密钥派生，首次配置引导用户备份主密钥。
  - 度量：未备份主密钥时，每次启动给出非阻断提醒；导出项目 JSON 永不携带密钥材料。
- **G3 切章 0 静默丢稿** ✅
  - 定义：自动保存只 `UPDATE` 主表，草稿态与版本态分离（F076）；切章/切项目/关页面前触发 dirty 拦截（F096/F097 复用同一拦截链）。
  - 度量：连续 1000 次切章/切项目/刷新操作，丢稿事件 = 0；契约用例覆盖「有未保存改动 → 拦截」分支。

### 1.2 AI 能力目标

- **G4 AI 结果由项目设定驱动 ≥ 80%** ✅
  - 定义：AI 调用的上下文由项目设定（世界观/目标平台/写作风格/角色/伏笔/术语）按需注入，而非整章全量堆砌。
  - 度量：抽样 100 次 AI 调用，≥80% 的请求体含 `projectSettings`/按需召回字段且非「整章正文 + 全部 relations + 全部 knowledge」无差别注入。
- **G5 26 种 AI 任务可用率 100%** ✅
  - 定义：同步辅助 + 编辑器 23 个 AI 按钮 + 关系设计 + 登记伏笔等共 26 种任务均可触发并返回结构化结果。
  - 度量：契约测试覆盖全部 AI 端点且全绿；未配置 Key 时降级本地 mock 并标注「本地演示模式」。
- **G6 AI 流式输出可用** ✅
  - 定义：`/ai/stream` SSE 透传、可中断（断开不落库）。
  - 度量：契约用例 31–33 全绿；mock 确定性假流可端到端跑通。

### 1.3 本地优先与一致性目标

- **G7 零运行时依赖** ✅
  - 度量：`npm ci` 后 `node server/index.js` 不触发任何第三方包下载；`npm ls --prod` 输出为空。
- **G8 离线/无 Key 核心可用** ✅
  - 定义：断网 + 无 Key 时，写作、版本、导出、大纲/结构视图等核心功能 100% 可用。
  - 度量：仅关闭 AI 相关能力，其余页面烟雾用例（11 条）全绿。
- **G9 长篇一致性可追踪** ✅
  - 定义：伏笔生命周期状态机 + 情节网格（≥5 条并行线索）+ 人物关系图/节点图；FTS5 检索 60 万字 p50 < 2ms，按需召回缩短 ≥50%。
  - 度量：契约用例 22–30 全绿；伏笔逾期在仪表盘标红。
- **G10 多格式成品导出** ✅
  - 定义：支持 JSON / TXT / Markdown / DOCX / EPUB + 附录（批注/术语表/时间线/伏笔清单）。
  - 度量：Word/阅读器可正常打开导出的 DOCX/EPUB；DOCX/EPUB 由 `node:zlib` 手写 OOXML/OPF，无第三方库。

### 1.4 工程化目标（正式开发方向）

- **G11 可维护前端** ✅
  - 定义：`novel-ai.js` 拆分为 `js/` 目录（≥6 个 ES module），单文件 ≤ 300 行，保持无构建（F089）。
  - 度量：前端模块化后既有用例全绿；无单文件超 300 行。
- **G12 工程化防线** ✅（持续）
  - 定义：TS 类型检查 / ESLint / Prettier / CI / 多环境配置纳入正式开发流程。
  - 度量：CI 全绿；新增 API 语义变更先补契约用例再动手（roadmap 纪律）。

## 2. 目标用户与画像

本产品是**单机单用户**工具，因此「多人协作角色」在本产品中实际由**同一作者的不同身份/工作阶段**承担，而非真正的多账号。

### 2.1 核心用户：单机写作作者（网文 / 长篇小说作者）
- **画像**：在本地写作、重视数据主权与隐私、不愿被云订阅绑定；有百万字级长篇或系列作品；对「人设/伏笔/世界观不崩」有强诉求。
- **痛点**：云端工具订阅贵、隐私顾虑、长篇一致性靠手工盯；通用大模型无故事记忆、无结构化组织。
- **诉求**：本地就能写、AI 辅助可信可控、结构清晰、切章不丢稿、导出多格式成品。

### 2.2 次要用户画像（同一作者的角色切换）
- **审稿/自查者**：自己回头审自己的章节，需要版本回滚、冲突校验、伏笔回收、AI 历史。
- **项目管理者**：同时维护多部作品，需要多项目切换、统一知识库、进度仪表盘与连续打卡。
- **发布运营者**：自己运营多平台发布，需要平台配置、定时发布、归档、多格式导出。

### 2.3 非目标用户
- 需要多人在同一文档实时协作的团队（见 §5 非目标）。
- 纯移动端碎片化写作用户（无原生 App，仅桌面/Web 本地）。

## 3. 用户故事（按场景，含验收标准）

> 每条故事格式：**作为 <角色>，我希望 <能力>，以便 <价值>。** 验收标准（AC）以 Given/When/Then 或清单形式给出。

### 场景 A：作者写作（核心）

- **US-A1 离线本地写作不丢稿**
  - 作为作者，我希望在本机离线状态下连续写作长篇，系统自动保存且不因切章/切项目丢失任何未提交内容。
  - AC：① 自动保存只更新主表、不生成冗余版本（F076）；② 切章前若有未保存改动弹出拦截（F096/F097 复用）；③ 断网环境下写作/版本/导出功能 100% 可用（G8）。

- **US-A2 项目设定驱动的 AI 续写/润色**
  - 作为作者，我希望 AI 续写与润色基于我这本小说的世界观、目标平台风格、角色设定来生成，而不是套用通用模板。
  - AC：① 触发续写/润色（F016/F014）后返回结构化结果；② 请求体携带项目设定与按需召回上下文（G4）；③ 划选文本时 AI 针对选区定向处理（F087，`selectedText` 取真实选区）。

- **US-A3 专注沉浸写作**
  - 作为作者，我希望进入全屏专注模式，只留编辑器、自动滚动到当前段落、可调节字号与行宽。
  - AC：① `focus-toggle`（F090）隐藏侧栏/顶栏/面板，仅留编辑器；② 打字机滚动在死区内小幅回中、不逐键强制滚动；③ 字号（F090a）/行宽（F090b）经 `localStorage` 持久化，普通模式同样生效；④ Cmd+S 行为不变。

### 场景 B：编辑部审稿（自查/审校）

- **US-B1 版本可追溯与回滚**
  - 作为自查作者，我希望每个章节有清晰的版本历史，能区分自动版本、手动存稿、★里程碑快照，并能回滚。
  - AC：① 版本面板按 kind 标注（F040/F097）；② 打快照命名后写入 `kind='milestone'`（F097）；③ 回滚后正文恢复且不动其他章节。

- **US-B2 冲突与一致性校验**
  - 作为自查作者，我希望系统自动校验情节冲突、回收伏笔、检查对白质量，给出可处理的问题清单。
  - AC：① 触发冲突校验（F032）返回问题列表；② 伏笔生命周期状态机可见（planted→resolved/abandoned，F084）；③ 逾期伏笔在仪表盘标红；④ 伏笔回收（F018）给出回收建议。

- **US-B3 AI 交互可审计**
  - 作为自查作者，我希望查看每次 AI 调用的历史与审计日志，确认 AI 看到了什么、改了什么。
  - AC：① AI 历史面板可打开（F006）；② 审计日志可打开（F007）；③ 系统日志可分级筛选/压缩/清除（F063–F067）。

### 场景 C：项目管理（多作品）

- **US-C1 多项目隔离与切换**
  - 作为管理多部作品的作者，我希望在多个项目间安全切换，且每个项目有独立设定与知识库。
  - AC：① 项目切换器在单项目时隐藏、多项目时可见（F096）；② 切换经 dirty 拦截；③ `?projectId=` → `X-Project-Id` → 默认项目解析，不存在返回 404 不静默回落（F079）。

- **US-C2 结构化大纲与情节网格**
  - 作为长篇小说作者，我希望用大纲树/场景卡片/情节网格组织卷→章→场景，并拖拽排序持久化。
  - AC：① 大纲树显示字数/场景数/伏笔（F083a）；② 章节拖拽排序持久化 `sort_order`（F083b）；③ 场景卡可拖到其他章或「未分配」桶（F083c）；④ Plot Grid 支持 ≥5 条并行线索、单元格循环节拍（F083d）。

- **US-C3 进度可视化与连续打卡**
  - 作为作者，我希望看到写作目标、进度仪表盘与连续打卡热力图，形成行为驱动。
  - AC：① 仪表盘展示连续写作天数与近 12 周热力图（F099）；② 会话计时显示本次时长与字数增量（F098）；③ 目标 deadline/note 可录入（F042，F087）。

### 场景 D：发布运营（发布/导出）

- **US-D1 多平台与定时发布**
  - 作为运营自己作品的作者，我希望配置多平台发布参数并设定定时发布，系统到点自动推送。
  - AC：① 平台账号名/规则可录入（F037，F087）；② 定时发布时间自选、留空兜底 +1h（F038，F087）；③ 懒扫描调度器到点推送、误差 ≤60s、重启任务不丢（F085）；④ 已发布章节可归档（F039）。

- **US-D2 多格式成品导出**
  - 作为作者，我希望把全书或单章导出为 Markdown / DOCX / EPUB，并附批注/术语表/时间线/伏笔清单。
  - AC：① 弹窗选格式 + 附录勾选 + 单章/全书（F092）；② 文件名 `<项目名>-<格式>-<日期>.<ext>` 中文文件名合规（RFC 5987）；③ Word/阅读器可正常打开；④ 导出不含密钥材料。

- **US-D3 数据逃生与回灌**
  - 作为作者，我希望完整导出全部业务数据并可导入回灌（含自动备份），避免单文件损坏即全书尽失。
  - AC：① 导出覆盖全部业务表 + 元信息（F060/F078）；② 导入支持 new（新项目）/replace（覆盖）且导入前 `VACUUM INTO` 整库自动备份（F078）；③ 单事务、失败整体回滚、非法载荷 400。

## 5. 非目标（明确不做）

1. **多用户服务端 / 账号体系 / 云端协作**：与「单机单用户、数据主权在本地」定位根本冲突。需求出现时属于新立项，而非本路线图扩展。
2. **云端存储与跨设备同步服务**：不提供官方云同步；如需异地容灾，走端到端加密云备份（远期想法池，待评估，见 §6）。
3. **移动端原生 App（iOS/Android 原生）**：仅桌面/Web 本地；移动端访问非目标体验。
4. **向量化 RAG / 外部 embedding API**：零依赖取舍下，采用「关键词 + TF-IDF/bigram 四维加权」召回（F081），关闭外部 embedding 依赖（roadmap 关闭 Q3）。
5. **真实发布平台对接 / 投稿变现链路**：`simulatePublish` 之上替换真实 provider 需逐平台单独立项（远期想法池），不在本期。
6. **实时多人协作编辑**：与 F074 鉴权模型及单机定位冲突。
7. **自研垂域大模型**：本项目是 BYOK 壳层，不训练/托管模型；拼生成质量非差异化方向。
8. **PWA 离线 / 只读分享**：F094/F095 未排期（见 §4.15 与 §6）。
